# 画面语义约束与逐句字幕同步设计规格

日期：2026-08-03

## 目标

修复三个共同影响成片可用性的问题：画面与旁白语义脱节、本地生成的人脸和手部畸形、字幕文字正确但出现时间与声音不一致。

每个分镜继续保留“旁白、图片提示词、视频提示词”三项可编辑内容，但视觉提示词必须以旁白中的可见事实为依据；字幕必须由真实配音时长生成逐句时间轴，页面烧录字幕与导出的 SRT 使用同一份提示。

## 视觉设计

### 默认人物安全策略

快速创作默认不生成可辨识的正面人脸和手部细节。人物确有叙事必要时，只允许使用背影、远景剪影、肩后视角、遮挡人物或资料画面。优先顺序为：

1. 与旁白直接相关的物体、道具、建筑、环境和自然景观；
2. 可识别剧情或主题的资料式画面、标题卡和环境细节；
3. 背影、远景剪影或被环境遮挡的人物；
4. 禁止正面人脸特写、眼睛特写、手部特写、多人肢体互动和复杂肢体动作。

该策略同时进入图片和视频提示词生成器。即使模型忽略规则，生成结果进入正式流程前也要经过本地文本审查，移除或改写高风险构图词。

### 旁白与画面对齐

视觉生成先为每段旁白产生一个结构化 `VisualScenePlan`，字段固定为可见主体、地点、动作、结果和证据。主体必填；其余字段只填写旁白实际提供的事实，不适用时使用空值，禁止为了满足结构而补造地点、结果或证据。图片提示词和视频提示词必须在同一次结构化响应中由这份事实计划派生，而不是分别从旁白独立发挥。禁止用与内容无直接关系的“宇宙、光芒、道路、流水、废墟”等象征画面替代具体事件。

图片提示词和视频提示词共享相同的核心场景事实。视频提示词只在图片场景基础上增加低风险的环境运动和镜头运动，不另外发明人物、地点或事件。

视觉事实保留旁白原文片段及对应英文翻译。原文片段由本地精确匹配验证；英文翻译再通过一次批量、`temperature=0` 的严格结构化忠实度审查，确认翻译为英文、没有补充原文不存在的地点/动作/氛围/证据。无效、空白或不完整的审查结果不得放行，必须进入既有重试并在耗尽后明确报错。该审查复用现有 LLM 服务，不增加新的外部依赖。

审查至少执行：

- 检查结构化计划的主体非空，并检查两类提示词都覆盖主体以及旁白中确实存在的地点、动作、结果或证据；空字段不参与覆盖率，也不能触发补造；
- 检查是否出现正脸、眼睛、手指、手部特写、多人互动或复杂动作要求；
- 检查图片与视频提示词的主体是否一致；
- 人物安全失败时进行确定性的安全改写；事实翻译审查失败时重新生成整组结构化计划，不静默改写或放行。

## 字幕时间轴设计

### 单一事实来源

TTS 生成后读取每段真实音频时长，并用 FFmpeg `silencedetect` 分析真实语音的开始时间、结束时间和中间停顿区间。旁白按中文标点和最大显示长度拆成短字幕，再通过有序匹配把句界放到最接近的真实停顿上，形成统一的 `SubtitleCue(text, start, end)` 列表。烧录字幕和 SRT 导出都读取这份列表，不再各自计算时间。

当前 TTS 抽象只返回音频路径，因此本次以本地音频停顿检测为唯一真实时间来源。以后如果 TTS 抽象端到端增加字词时间戳，可以在保持 `SubtitleCue` 接口不变的情况下替换检测结果；本次不声明或实现一条不存在的数据通路。只有音频中确实没有足够停顿可供匹配时，剩余句界才按字符数和标点权重在相邻真实停顿之间插值，并记录降级日志。

### 时间分配

- 每个分镜的第一条字幕从 `silencedetect` 测得的实际语音开始时间出现，前导静音不显示字幕；
- 每个短句的结束位置优先吸附到真实音频停顿的中点；
- 多个候选停顿通过保持句子顺序的最小误差匹配选取，不能交换句序；
- 仅在缺少停顿候选时，才按有效字符数及逗号、分号、句号、问号和感叹号权重插值；
- 最后一条字幕在 `silencedetect` 测得的实际语音结束时间消失；音频文件内部的前导/尾部静音以及镜头尾部静音均不显示字幕；
- 普通顺序拼接时，下一段字幕偏移按最终片段时长累计，因此 `min_segment_duration` 和 `scene_trailing_silence` 形成明确的无字幕区间；使用当前顺序音轨式转场时，偏移按照后期实际使用的原始配音时长和显式旁白间隔累计；
- 转场不得改变顺序旁白的字幕时间；如果以后增加明确的旁白间隔，该间隔必须作为无字幕区间进入同一时间轴。

本次采用本地音频语音区间/停顿检测优先、标点加权插值兜底的两级策略，不引入语音识别或联网依赖。

### 烧录方式

HTML 模板不再把整段旁白烘焙为静态图片。视频合并完成后，程序用统一 SRT/ASS 时间轴一次性烧录动态字幕，并保留未烧录的同名 SRT 文件供平台上传。关闭字幕时既不烧录，也不显示模板静态文字。

字幕样式继续使用现有字体、位置、颜色、字号和描边设置。

## 数据与兼容性

- `StoryboardFrame` 分别存储 `audio_duration` 和最终 `duration`。字幕提示不作为第二份持久化事实源，由统一规划器按需生成。
- 持久化服务保存并恢复 `audio_duration`；旧任务缺少该字段时，如果音频文件存在就重新探测音频，否则回退到已知片段时长并记录兼容性警告。
- 已有片段被复用而跳过 TTS 时，也必须从对应音频重新探测 `audio_duration`，不得保持为零。
- 用户编辑后的旁白仍是配音、视觉规划和字幕文字的唯一来源。
- 本次不增加联网素材检索、语音识别、人物修复模型或第三方提示词数据库。

## 测试要求

自动测试至少覆盖：

1. 中文旁白可按标点及显示长度拆为非空短句，原文字符顺序不丢失；
2. 有真实静音停顿时，字幕句界吸附到停顿区间而不是字符比例估算；没有足够停顿时才触发确定性插值兜底；
3. 含前导和尾部静音的音频中，第一条从真实语音开始出现，最后一条在真实语音结束时消失；提示连续无重叠；
4. 普通拼接按最终片段时长累计下一段偏移，镜头尾部静音不显示字幕；顺序音轨式转场按实际音轨布局累计；
5. SRT 导出与烧录输入使用相同提示列表；
6. 开启字幕时模板不再静态写入整段旁白，关闭字幕时不烧录；
7. 图片和视频生成提示都包含默认人物安全规则；
8. 高风险人脸、手部和复杂人物动作词会被本地审查改写；
9. 一次结构化视觉计划同时产出事实字段、图片提示词和视频提示词，两类提示词覆盖同一主体和事件；
10. `audio_duration` 的保存、加载、旧任务恢复和复用片段重新探测均有测试；
11. 现有完整测试套件继续通过。

## 验收结果

生成一段含多个逗号和句号的旁白后，字幕应随着声音逐句切换，最后一句在旁白结束时消失；画面提示词应能指出旁白正在介绍的具体对象或事件，默认不要求生成清晰正脸或手部。
