# 分镜解说与画面提示词设计规格

日期：2026-08-02

## 目标

将“先生成文案草稿”升级为可检查、可编辑、逐镜对应的创作结果。每个分镜同时生成但分开显示：影视解说旁白、图片提示词、视频动态提示词。生成视频时直接使用用户在页面上确认或修改后的内容，不在后台偷偷换成另一套提示词。

本次同时修正影视盘点内容的写作倾向：输出应当像影视解说，而不是围绕情绪反复抒情的鸡汤文。

## 用户体验

生成完成后，草稿区由一个大文本框改为按顺序排列的分镜卡片。

每张卡片包含：

1. **旁白解说**：默认展开并可编辑，内容是观众最终听到的解说。
2. **画面提示词**：独立区域，可展开查看和编辑。
   - **图片提示词**：描述静态首帧或插图，包括主体、人物、场景、构图、光线、情绪和画风。
   - **视频提示词**：描述该画面如何运动，包括人物动作、环境变化、镜头运动、节奏与连续性。

卡片标题使用“分镜 1、分镜 2……”；三项始终共享同一个分镜编号。默认只展开旁白，提示词折叠，以保持主页面简洁。用户可以单独修改任意一项。

“清空草稿”会同时清空三类内容。“生成视频”读取当前卡片中的全部编辑结果。

## 影视解说规则

当主题被识别为影视、动漫或剧集盘点时，每段旁白必须包含：

- 明确的作品、剧集或条目名称；
- 具体人物及其处境；
- 可描述的剧情事件、冲突或关键行动；
- 该条目入选的具体原因；
- 必要时说明情绪落点，但不能用抽象感悟代替剧情介绍。

禁止仅使用“温暖、治愈、成长、感动、平凡中的光”等抽象词堆砌内容。盘点五集就生成五个条目，不额外占用分镜写开场或总结。

在没有可靠资料来源时，不把模型猜测包装成官方集数或官方标题。界面不声称内容已经联网核实；联网事实核验作为后续独立能力。

## 生成架构

首次草稿生成采用两阶段流程：

1. **生成旁白**：根据主题、栏目配方、目标分镜数和长度生成逐镜影视解说。
2. **生成视觉提示词**：以已经生成的全部旁白作为上下文，分别生成等量的图片提示词和视频提示词。

两阶段比一次返回巨型 JSON 更容易复用项目现有的图片、视频提示词生成器，也能独立重试失败部分。最终在界面层组合成统一的分镜草稿模型：

```text
SceneDraft
  index
  narration
  image_prompt
  video_prompt
```

每组结果必须与目标分镜数完全一致。任何一组数量不一致都不能静默错位。

## 与正式视频流程的衔接

页面保存结构化的分镜草稿，而不是只保存换行拼接的旁白。

点击“生成视频”时：

- 旁白直接用于配音和字幕；
- 图片模式直接使用对应的 `image_prompt`；
- 视频模式直接使用对应的 `video_prompt`；
- 如果某条提示词被用户清空，只允许对该空缺项补生成，并在界面给出提示；
- 不覆盖用户已经编辑的提示词。

为兼容旧流程，旧的纯文本草稿仍可转换为仅包含旁白的分镜草稿，提示词在需要时补生成。

## 状态与错误处理

- 生成过程中显示当前阶段：生成解说、生成图片提示词、生成视频提示词。
- 旁白生成失败时不进入提示词阶段。
- 图片或视频提示词某一阶段失败时，保留已经成功的旁白和另一类提示词，并显示可重试入口。
- 用户修改主题、栏目或分镜数后，现有草稿标记为可能过期，但不自动删除。
- 所有编辑内容保存在当前页面会话中，普通界面刷新不应因为组件重绘而被覆盖。

## 测试要求

自动测试至少覆盖：

1. 影视盘点提示词要求具体剧情、人物行动和入选理由，并禁止纯情绪泛化。
2. 一次草稿生成得到数量相等的旁白、图片提示词和视频提示词。
3. 分镜卡片把三类内容分开显示，并维持正确编号对应关系。
4. 用户编辑后的提示词原样传入正式视频流程，不被再次生成覆盖。
5. 单类提示词失败时保留其他已成功内容。
6. 旧的纯旁白草稿仍能进入视频生成流程。

## 本次范围

本次实现本地生成、展示、编辑和正式流程复用。联网检索官方剧集资料、事实引用和来源展示不包含在本次范围内，可在后续作为“联网核实”能力单独设计。
